# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Working rules (apply to every task)

- Do exactly what the task lists. No extra files, features or refactors.
- Never run, test, install, build or start anything, unless the task explicitly asks you to run something. Only write files. The user runs commands themselves at planned checkpoints.
- Do not create or modify `RUN_COMMANDS.md` unless the task explicitly asks.
- Read docs completely; do not search them for keywords.
- If a task conflicts with a doc, follow the task and print one line: "CONFLICT: <what> vs <document>".
- End every task by printing only the list of files created/changed.

## What this is

Ultron: an offline multi-agent desktop assistant for Windows 11. A Tauri + React/Three.js HUD talks over a loopback WebSocket to a Python FastAPI + LangGraph backend; local LLMs run through Ollama on a 4 GB GPU. The design lives in the numbered docs at the repo root (`01_product_requirements.md` … `06_phase_wise_plan.md`). `03_architecture.md` and `04_system_design.md` are the ones to read before changing structure.

## Decisions made

- **Ollama**: `OLLAMA_MAX_LOADED_MODELS=3` (CPU router + CPU embedder + one GPU worker).
- **Music**: local library first (fuzzy match on `registry_media`, then `mpv`). If there is no local match and the internet is reachable (cached TCP probe, 1.5 s timeout, 30 s cache), play via `mpv` + `yt-dlp` (`"ytdl://ytsearch1:..."`). "Open YouTube Music" explicitly goes through the web agent. Offline with no local match says so. The online path is a second audited egress exception alongside the Playwright allowlist, and it fails visibly.
- **GPU worker residency is per RUN, not per node**: the docs' per-node eviction contradicts their own zero-swap claim. `worker()` does not unload on exit; `release()` evicts when the run ends.
- **Routing is hybrid** (`graph/supervisor.py` `decide()`): one keyword hit -> no model call; several hits -> the LLM arbitrates, and on disagreement (or NONE) the priority dev > rag > web > os wins; no hits -> the LLM alone. Reason: the 1.5B router scored 76.7% on its own (it over-routes chit-chat and confuses app control with dev/web). The router's few-shot examples in `llm/prompts/router.md` (after `## EXAMPLES`) are sent as chat turns. The 30 main cases in `tests/routing_cases.py` were written together with the regexes, so the held-out set (`tests/routing_cases_heldout.py`) is the honest measure; the user adds their own real utterances to it. `scripts/check_routing.py` takes `--mode {llm,hybrid}` and `--set {main,heldout,both}`.
- **The RAG node publishes its own tokens** (answer, then the Sources footer) and sets `additional_kwargs={"published": True}` on its `AIMessage`; `run_graph` in `orchestrator.py` records such a message and only sends the done marker.
- **CRAG grading runs on the CPU router**: top 4 chunks, 900 characters each, one-word yes/no answer, stop at 3 relevant. The loop costs CPU seconds, not VRAM, and a failed retrieval never loads the GPU worker.
- **Dialogue examples are injected into every worker prompt** (`style_block`) and are never retrieved as evidence.
- **Worker prompts are honest about missing tools**, so Phase 4 answers cannot fabricate actions or notes. The Phase 5/6 prompts rewrite them.
- **Placement is verified**: the manager checks `/api/ps` after each load and publishes `warn` `error` events on partial GPU offload of the worker or a CPU model found on the GPU.
- **Embedder warm-up** goes through `/api/embed`, not `/api/generate`.
- **Event schema**: `tool_call.agent`, `tool_call.args_preview` and `screenshot.action_id` are optional. `pong`, `snapshot` and `gesture` are extra event types. Envelope `id` and `ts` are optional so the frontend `resync` frame validates. `"x-direction"` is a custom keyword.
- **Lexical retrieval is full-text search**: OR-ed distinctive words (`memory/fusion.py` `build_or_query`) against `chunks_fts`, fused with the vector results by RRF. The blueprint's pg_trgm `content % query` compares a whole question with a whole chunk and returns almost nothing.
- **`pick_collection` returns exactly one collection** (`personal` or `scripture`), never both; "my notes" wins over scripture words. Verses are looked up by metadata (`parse_verse_ref` -> chapter/verse), not by similarity.
- **Vectors are passed as `$n::text::vector`**, so no pgvector codec is registered. The pool (`memory/db.py`) applies the hnsw settings in the `setup` callback, because asyncpg resets session state when a connection is released.
- **Tauri session token**: debug builds use `ULTRON_SESSION_TOKEN` or `"dev"` (matches `SESSION_TOKEN=dev` in `backend-ai/.env`). Release builds generate a random token; backend delivery is a Phase 8 TODO.
- **The OS agent uses the CPU router as the intent decider (regex is only a fast path), not the GPU worker** (the docs say the worker). Reasons: actions are registry-backed, "open notepad" must not pay a 3 s model swap, and 3B tool calls are unreliable.
- **Mood requests** ("something calm") use `nomic-embed-text` embeddings over title / artist / tags in `registry_media` (cosine similarity >= `media_embed_min`); they need `python ..\scripts\embed_media.py` after each library scan. The online music path (`play_online`, yt-dlp through mpv) is the second audited egress exception, and mpv is a single long-lived process shared by all playback and controls.
- **The web agent takes a deterministic site-search fast path** ("search X on Flipkart", "open youtube music"): parse, open the URL, read the page once, and let the worker summarise it; the worker only holds the GPU while it summarises. Everything else runs a best-effort generic loop of JSON steps (`goto`, `read_page`, `click`, `type`, `press`, `finish`) decided by the worker, capped by `browser_step_limit`. Page text is always wrapped in `<page_content>` and treated as data, never as instructions. An off-allowlist host always needs a `send`-risk confirmation, and a click's risk comes from `click_risk()`.
- **Graceful close is automatic** unless `CONFIRM_GRACEFUL_CLOSE=true`. PRD goal 5 lists closing an app under confirmation, while FR-3.3 says graceful close is automatic and only the forced close needs confirmation.
- **Every side-effecting tool goes through `registry.gate`**, which checks the agent's allowlist, applies the risk policy (confirm for send / destructive, audit to `episodes` for write and above) and lets a caller escalate one call's risk.
- **STT endpointing is RMS energy-based, not Silero VAD** (the docs say Silero). Silero's `torch.hub` download needs runtime network access, which breaks the offline rule, and torch is heavy for this; RMS mirrors what `useAudioLevel.js` already does for the orb. Tune `stt_rms_threshold` and `stt_silence_ms` first if a mic or room gives false triggers; Silero stays a documented future upgrade.
- **The STT engine is one persistent thread** (`SttEngine` in `sensors/stt.py`), armed through a `queue.Queue`, cancelled through a `threading.Event`, and bridged to asyncio with `run_coroutine_threadsafe` (events go to the bus, the final text to `on_final`).
- **`tts.speak()` must be launched with `asyncio.create_task` by the caller and never awaited inline**, so a long answer cannot block a new run from starting. `tts.barge_in()` is how a new turn (voice or text) interrupts ongoing speech; call it before arming the mic or starting a run.
- **There is no pyautogui in v1.**
- **Terminal reading uses OCR plus the worker instead of moondream.**
- **Postgres checkpointer is on by default since Part 8.2** (set `CHECKPOINTER=memory` in `.env` to turn it off) (`graph/checkpointer.py`, verified by `scripts/check_checkpointer.py`). A failure falls back to the in-memory saver with a `startup_warnings` entry (source `checkpointer`).

## Architecture (the parts that span files)

**One event bus, one direction of truth.** The backend owns all state and the frontend only renders events. `bus.py` (`EventBus`) is the single input to the WebSocket layer. Sensors, the VRAM poller and the LangGraph graph publish to it, and `orchestrator.py` subscribes one queue per client and pumps it out. The graph must never know a UI exists.

**Backpressure rules live in `bus.py`.** Queues are bounded at 256. Event types are classified as `LOSSY` (`audio_level`, `vram`, `token`) or `CRITICAL` (`state`, `error`, `graph_node`, `confirm_request`). On overflow, lossy events are dropped, and a critical event evicts one queued lossy event. When adding an event type, decide which class it belongs to.

**The WebSocket contract is `shared/events.schema.json`.** It is the source of truth for the envelope `{v:1, id, ts, type, payload}` and for both directions of traffic. `shared/gen/` (`events.d.ts`, `events.py`) is codegen output and is gitignored apart from `.gitkeep`. Change the schema first, then regenerate. The tables in `03_architecture.md` §5 describe each event's payload and what it drives in the HUD.

**GPU has exactly one tenant at a time.** The router (`qwen2.5:1.5b-instruct`) and the embedder (`nomic-embed-text`) are pinned to CPU. Exactly one worker model (`qwen2.5-coder:3b`, or `moondream` for vision) is loaded on the GPU at a time. It is held under an async lock in `llm/ollama_manager.py` and evicted with `keep_alive=0` on scope exit. `config.py` encodes this with `CPU_MODELS`, `GPU_MODELS` and `VRAM_COST_MB`. Every routing decision is also a memory decision, and model load/unload phases are published as `model` events so the HUD can show the cold-load gap.

**Agents are isolated by capability, not by prompt.** Each of the dev, web, OS and RAG workers is built with its own tool list, and `tools/registry.py` refuses to return tools outside that list. Tools are classified by risk at registration time. Anything above write-local risk must round-trip through `confirm_request` / `confirm_response` on the bus, and a timeout counts as denial (`tools/approvals.py`). Per-agent role prompts are in `llm/prompts/*.md`.

**Graph shape.** A LangGraph supervisor node (`graph/supervisor.py`) routes to `dev_agent`, `web_agent`, `os_agent` or `rag_agent` and each returns to the supervisor until FINISH. State is `UltronState` in `graph/state.py`, and checkpoints go to PostgreSQL.

**Action registries.** Apps, media and contacts are resolved by fuzzy lookup (`tools/resolve.py`, rapidfuzz) against the `registry_apps`, `registry_media` and `registry_contacts` tables (`memory/schema.sql`, `scripts/seed_registry.sql`, `scripts/scan_music.py`). The P6 hands work depends on these tables existing early.

**Offline is an invariant.** No runtime network egress beyond loopback (Ollama on `127.0.0.1:11434`, PostgreSQL, the backend on `127.0.0.1:8765`). The Tauri CSP forbids remote origins and fonts and libraries are bundled. Auth is loopback binding plus a session token that Tauri generates at startup and passes as a query parameter. The audited exceptions are the Playwright allowlist and the online music path (see "Decisions made").

**Fail visible.** Exceptions, tool timeouts and model-load failures should become `error` events shown in the HUD, not silent failures.
